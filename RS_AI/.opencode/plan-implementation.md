# Implementation Plan – Tauri v2 for filen_gui

## Roadmap (Phase Split)
| phase | mô tả | phụ thuộc | ưu tiên |
|-------|-------|-----------|---------|
| 1 | Scaffold Tauri project (src-tauri, frontend/Vite) | - | 1 |
| 2 | Core Rust commands mapping (operations.rs → Tauri commands) + async wrappers | 1 | 1 |
| 3 | UI Shell – HTML layout (top bar, sidebar, dual‑pane, bottom transfer drawer) | 1 | 1 |
| 4 | UI Components – NeonButton, NeonInput, NeonTableRow, NeonNavTab, NeonDropZone, NeonModal, NeonProgressBar (CSS + TS) | 3 | 1 |
| 5 | State Management – TS interfaces (PaneState, AccountState, TransferItem, ModalState, ServersState, ClipboardState) + event bus | 4 | 1 |
| 6 | i18n implementation – t(key) lookup, lang_id dictionary loading, hot‑switch | 5 | 1 |
| 7 | Theme runtime – load JSON theme, merge default/user, apply CSS variables, hot‑reload watcher | 5 | 2 |
| 8 | Drag‑and‑drop OS file handling – Tauri drag‑drop plugin + backend handling | 3 | 2 |
| 9 | Tests – unit tests for commands, integration tests for UI (Playwright) | 2,4,6,7,8 | 1 |
| 10 | Final verification – run `cargo check`, `cargo test`, `cargo clippy` across workspace | 9 | 1 |

## Acceptance Criteria
- All commands from `operations.rs` and `transfer.rs` exposed as async Tauri commands.
- UI matches Neon design (colors, glow, glassmorphism) on Windows/macOS.
- i18n works for VI/EN with all keys defined in `i18n-and-themes.md`.
- Theme can be changed at runtime without reload.
- Drag‑and‑drop from OS into explorer panes works on Windows/macOS.
- No lint warnings, all tests pass.

## Notes
- Use `tauri-cli` v2 and `vite` for frontend.
- Keep `src-tauri/commands` thin wrappers that call existing functions in `operations.rs`/`transfer.rs`.
- Frontend code lives in `frontend/` (generated by `npm create tauri-app`).
- All new files must be added to the repo; existing files remain unchanged except for command annotations.
